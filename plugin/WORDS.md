# Words

The plugin uses the OATS Desktop's words for every act, state, label, notice and refusal (the UX
standard, section 2). This file holds each place where bb's nature, or the plugin's, changes a word:
what the Desktop says, what the plugin says, and why. Nothing else is reworded.

The tables the plugin copies from the Desktop whole are named in the header of the file that holds
them: `app/ui/text.ts` (the display filter), `app/ui/words.ts` (the needs-input words and times, an
instance's name as words).

| Thing | The Desktop says | The plugin says | Why |
|---|---|---|---|
| The state of an agent, as a word beside its mark | no word: the dot alone, named "running", "stopped" or "status unknown" for a screen reader | **Working**, **Idle**, **Needs you**, **Stopped**, **Failed**, **Unreachable**, each beside its mark | The standard: a state is always a mark and its word. bb's kernel rows say more than running or not: a session that fell back to a shell (Failed) and one the kernel cannot reach (Unreachable). |
| The accessible name of a state's mark that stands alone | "running", "stopped", "status unknown", "Needs input" | the same four; "failed" and "unreachable" for the two states the Desktop does not draw | The Desktop's names where it has one. |
| An agent the kernel says neither runs nor is stopped | "status unknown" (a grey bullseye) | **Idle** (named "status unknown") | On bb the kernel reports an agent that waits between turns as neither running nor stopped: it is there and not working, which a person reads as idle. |
| Automations: the notice that the host scheduler is off | "The scheduler is not running on this computer, so nothing here runs until it is enabled." (one sentence in a banner) | title **The scheduler is not running on this computer**, then "Nothing here runs until it is enabled." | The standard's notice has a title: the sentence's first clause is the title, the rest follows. No word is changed. |
| Automations: the notice that this computer has no host name | "This computer has no host name, so it runs none of the workspace's schedules. Name it in this deployment's local settings to take on the ones assigned to it." | title **This computer has no host name**, then "It runs none of the workspace's schedules. Name it in this deployment's local settings to take on the ones assigned to it." | The same: a title, then the rest of the Desktop's sentence. |
| Automations: a list that could not be read | the kernel's message alone, in the error colour | title **Schedules could not be read** (or **Triggers …**), the kernel's message under it, its code after, Retry | The standard: a person's words first, the kernel's code after. The Desktop has no sentence of its own here. |
| Automations: a next run that is in the past | "Next 3 h ago": `Next ${next.label}` with its relative time, whatever the time is (`packages/desktop/renderer/views/automations.mjs:434`, and a row's page at `:591`) | the same, "Next 3 h ago" | Not a difference, written here so nobody takes it for a defect of the plugin. The kernel works out the next run when it answers the list, so it is in the past only in a list kept after a read that failed, and that list says its age. |
| Automations: a run that did not happen, in Recent runs | the outcome alone ("launch failed"); the kernel's error is not shown | the outcome, then **Details**, which opens to the kernel's message and its code | An addition: why a run did not happen is the first thing a person asks. The standard: a person's words first, the kernel's one press away. |
| Automations: what Run now did | one line, "<id>: <outcome> · <the kernel's error> · <its reason>" (`packages/desktop/renderer/views/schedules.mjs:309`) | title **<id>: <outcome>** ("local/hourly-check: Launch failed"), then the kernel's error and its reason as lines under it, its code after | The kernel's text goes through the display filter by itself: an error that is withheld (it looks like a secret) still leaves which schedule and what happened. |

## The roster: the sidebar, the thread's row, the confirmations

| Thing | The Desktop says | The plugin says | Why |
|---|---|---|---|
| The age of what is still shown | "just now", "45s ago", "3 min ago", "at 14:05" (`observedAgeText`) | always relative, one form: **less than a minute ago**, **12 min ago**, **3 h ago**, **2 d ago** (`readAge`, `app/ui/words.ts`) | The lead's ruling on the stale state: a read that could not be made again must not read as fresh, and one form of age on a screen. |
| OATS cannot be read: the notice's title (`app/roster/unreadable.tsx`) | "Couldn't reach <host>" for a server that does not answer; the kernel's message alone for the rest | a title per cause, in a person's words (**OATS is not installed on <machine>**, **OATS did not answer on <machine>**, **OATS could not read this deployment**, **No OATS deployment found on this machine**, **bb could not list its threads**…), then one sentence of what to do, the code after the words, the kernel's message under Details | The plugin reads OATS through bb's host, so it has causes the Desktop has not (no `oats` on the machine, no deployment chosen, bb's own thread list); the standard asks for a person's words first and the code after. |
| The roster kept while OATS cannot be read | "Last observation — <age>" over the roster, "showing what was read <age>", actions held | ONE notice (`app/roster/unreadable.tsx`), with the age said once and in one form: **Showing what was read <age>.** | The Desktop's sentence; its second line with the same age is left out (one form of age, said once: the lead's ruling R4). |
| Acts on a roster that is the last one read | held | HELD too: Stop, Start, Restart and Retire stay in their place, off. The notice says **Press Retry: Stop, Start, Restart and Retire come back when OATS is read again.**; each act that is off says **Comes back when OATS is read again** (a menu entry's detail, a button's title) | The sentence names Retry first, so that a person does not reach for bb's own Stop out of a dead end (the lead's ruling R4; it reversed "offered, as of <age>"). |
| The same where the notice has no Retry (the bb server has several machines and none is chosen: only the settings mend it) | no such state | **Open settings: Stop, Start, Restart and Retire come back when OATS is read again.**, with the link Open settings, on the one-line notice too | The sentence names the act the notice has. |
| An agent the kernel refuses as one it does not know (a stop plan or a retire plan refused with E_SESSION_UNKNOWN) | **Forget…** on a row its server no longer lists | the row says **Not in OATS any more** in its state's place until the next roster; the confirmation says "<name> is not in OATS any more", "Nothing was changed." Any other act on such an agent shows the kernel's refusal as it is. | bb has no server-side roster to forget from: the next read of `oats status`, made right after every act, drops the row. |
| An agent's name | the instance's name as words ("Oats expert maintainer lanes") | the same, everywhere the plugin draws an agent (`agentName`, `app/ui/words.ts`: the Desktop's `instance-display-name.mjs` through the display filter); bb's title for the thread is never the name | The lead's ruling R1. The provider titles the bb thread with the same words. |
| The thread row's facts | instance of, Parent, Owning human, Messaging ID (the instance panel's) | the same four labels, and **Children** | One vocabulary for one fact (R3); the team's id is not in a label. |
| The way to the instance panel, on a thread | (the panel is beside the roster) | the button **Instance panel** | It says what it opens. |
| The thread's row, an agent that waits with no claim of the kernel's | (no such case: the Desktop has no session of its own) | **bb shows its question in this thread** | The question is bb's own pending interaction; the kernel recorded no claim. |
| The thread's row, an agent whose session ended in a shell | "Its session ended" in the instance panel | **Failed** · **Its session ended**, with Restart | The Desktop's words; the state's word beside them is the plugin's (first table). |
| The thread's row, an agent the kernel cannot reach | the kernel's message | **Unreachable** · **OATS cannot reach its session**, with Retry; the kernel's message (often a URL or an error's code) under **Details**, after "OATS says:" | A person's words on the line; the kernel's text one press away (the standard, section 2). |
| A row of an agent with no bb thread | the row is the instance, whatever runs it | "<state> · <soul> · **runs in tmux**", or "… · **its bb thread is gone**" | In bb an agent is a thread; one without a thread is said to be so, and opens its own page. |
| Nobody waits | "Nothing needs you." | the same | none. |
| The act that makes an agent | **New agent** | the same, a button at the roster's foot | none. |
| The plugin's pages in the sidebar | one **Workspace** row (a page with tabs) | the heading **Workspace** over a row per page | bb's pages are routes, not tabs of one page; the Workspace page with its tabs is a later piece. |

### Since when, by state (the status line of a thread's row)

A time is said only where the kernel recorded one; the plugin invents none.

| State | The time said | The kernel's fact | Where |
|---|---|---|---|
| Needs you | "waiting 12 min (since 14:03)" | the claim's `since` (`oats status`: `waitingOnYou.since`). None when the question is bb's own: OATS recorded no claim. | every place |
| Working | "session started 14:03" | the row's `startedAt`: when the session started, said as that (the turn it works on may be newer) | every place that draws the status line |
| Stopped | "since 14:03" | the time of the instance's last `stopped` event (`oats instance events`) | the open thread's row: one read for one agent, made again each time the agent is seen to turn stopped; an event older than the session's start is not this stop's, and no time is said. The sidebar's rows and the panel's header say no time. |
| Idle | none | the kernel records none | |
| Failed | none; the reason in its place: "Its session ended" | the kernel records none (a session that died wrote nothing) | |
| Unreachable | none; the reason in its place: "OATS cannot reach its session", with the kernel's own message under Details | the kernel records none | |

## The home

| Thing | The Desktop says | The plugin says | Why |
|---|---|---|---|
| The summary line (`app/home/home-words.ts` `summaryLine`) | "24 agents · 21 running · 3 need you · 0 stopped", and "· N status unknown" when there are any: the kernel's liveness (`packages/desktop/renderer/views/home.mjs` `summaryLine`) | "8 agents · 3 working · 3 need you · 1 idle · 1 stopped", and "· N failed", "· N unreachable" when there are any | The plugin's states (the first table of this file): the line counts by the one function every place reads for an agent's state, so its numbers are the sidebar's. Working and need you are always said, as the Desktop says running and need you; idle and stopped only when there are any, since the plugin has more states than fit a line of zeros. "N need you" whatever the number, as the Desktop's line and the sidebar's foot. |
| The agents at work | **Running**, "Show all N running" | **Working**, "Show all N working" | The plugin's word for the state (first table). "Show fewer" is the Desktop's. |
| Agents that finished and were not looked at | (no such group) | **Finished, not looked at** | bb knows which threads a person has not read; the Desktop has no such fact. Not drawn when there is none. |
| The reply on a card | (none: a card of the Desktop's Home opens the instance, where its terminal is) | a box on the card, "Write to <name>…", named "Reply to <name>" for a screen reader, with **Send** | An addition: in bb an agent is a thread a person writes in, so the card can take the answer. It is bb's own send, as the person at the screen. On the card and named for the agent, so a message cannot go to another one than the one read. |
| The order of what needs you (D-054) | newest first | those with a thread in bb first, then those without; within each, newest first | On the Desktop every row is answered by opening it. Here an agent on tmux cannot be answered from bb: the ones a person can answer on the spot are not hidden behind "Show all N" by ones they cannot. |
| A card whose agent has choices to pick from | the options are the answer (the board's question) | the choices as buttons; after one is pressed, "Answered: <choice>. Waiting for the agent to go on." | In place, on the card. What was answered is said until the agent goes on, so a press is never silent. |
| A card whose request cannot be answered on it | (opens the instance) | "bb shows its request in its thread: open the thread to answer it." / "It waits for an approval, and bb lists no request to answer here: open its thread to see what it waits for." | The card says where the answer is, and why it is not here. |
| A message beside a request that has an answer of its own | (none) | **Write a message instead**, then "A message does not answer its request: it grants nothing, and the request stays open." | A message is bb's own send into the thread; it must not read as a way to grant an approval. |
| A card of an agent on tmux | (the same card; the Desktop opens its terminal) | "It runs in tmux on <machine>, where bb cannot write to it. Answer it in its terminal there:" with `oats session attach --home <its home>` to copy; **Open its page**, "Open its page shows who it is and how it runs." | The plugin never types into a session and bb has no terminal: the card gives the way there, in the kernel's own command. |
| A card of an agent whose bb thread is gone | (no such case) | "Its bb thread is gone, so nothing can be sent to it from here." | bb can send only to a thread it has. |
| The button that opens an agent from its card | the row is the control | **Open thread**, or **Open its page** for an agent with no thread | The button says where it leads. |
| A card while the roster is the last one read | acts on a held roster are held | the choices and the reply are off, with "Held until OATS is read again: what is shown may have changed." | The Desktop's rule, said as a reason beside the control (the standard: a control that is off says why). |
| A sent reply, a reply or an answer that failed | (no act on a card) | "Sent to <name>." on the card; a notice on the card titled **The message was not sent** / **The answer was not sent**, with what bb said | In place, on the card it is about. |
| Who started an agent, in Home › Agents | "started by <human or parent>" | the same; a parent by its name as words | none. |
| The empty workspace | "OATS runs your agents: each one is a soul at work on a machine of yours." / "Start one, and Home shows what needs you and what you have.", then three keys (New agent, Command palette, Home) | the same two lines, the first as the title; **New agent** is the button in the heading's row, drawn there as the thing to press | bb has its own keys and command palette, and the plugin adds none: the one act is a button. |
| **New agent** on the Home | (none: the Desktop's Home has no such button; its act is the sidebar's foot, always in view) | **New agent** in the heading's row of every home; off, with the reason beside it, behind the CLI card ("Off until a compatible oats CLI is installed.") and while the roster is the last one read ("Held until OATS is read again: what is shown may have changed.") | At a phone's width bb keeps its sidebar in a drawer, and the home is what a person sees: the act that makes an agent has to be on it. |
| The page's name | the window's Home | the heading **Home** on the page; bb's own bar over it says **OATS**, the plugin's entry in bb's navigation, with bb's own close button | bb names a plugin's page by its entry in the navigation; the page says which page of OATS it is. |
| The CLI card, an oats older than the plugin works with (D-004) | "Compatible oats CLI required", "Spawn, Start and other changes run through the installed oats CLI. Reads and terminals keep working without it.", Detected, Required ("<range> with desktop API 1"), `npm install -g @awebai/oats@<the Desktop's version>` with Copy, Choose oats…, Retry, CLI setup docs | **Compatible oats CLI required**, "Everything the plugin shows and does runs through the installed oats CLI.", **Detected**, **Required** ("0.70.0 or newer, with desktop API 1"), `npm install -g @awebai/oats@0.70` with Copy, and **Check again** | The plugin has no read of its own: its reads go through the CLI too, so the Desktop's second sentence would be false here. The command installs the newest release of the minor the plugin was tested with (`kernel/compat.ts`). Which `oats` runs is the plugin's setting `oatsBin` (bb's settings), not a button. The Desktop's **Retry** is **Check again** here: it says what the press does (the version is read anew), where "Retry" would read as trying the install again. |
| The same card for an oats whose version cannot be read | Detected "unknown — no CLI detection reported" | Detected "unknown: oats answered no version the plugin can read" | A sentence that says what happened here: `oats` ran, and what it printed for its version is not one. |
| An oats that speaks a newer desktop API (D-008) | "This Desktop is older than the installed oats CLI", "The installed oats CLI is <v>, which speaks a newer desktop API than this Desktop's (1). Install OATS Desktop <v> to use it; reads and terminals keep working meanwhile." | **This plugin is older than the installed oats CLI**, "The installed oats CLI is <v>, which speaks a newer desktop API (<n>) than this plugin's (1). Update the OATS plugin to use it." | It is the plugin that is older. No promise that reads keep working: the plugin's reads are the answers whose version moved. No npm command, as on the Desktop. |
| An oats of a later minor than was tested (D-007) | "This Desktop was tested with oats CLIs up to X.Y; the installed CLI is <v>. Stop, Remove, schedules, triggers and every other change except Spawn, Start, Restart, colour and background are off until you install OATS Desktop <v>." | "This plugin was tested with oats CLIs up to 0.70; the installed CLI is <v>." | The first sentence, said of the plugin. The plugin turns no act off for a later minor (the specialist's decision): every act goes to the kernel, which plans it or refuses it. |
| New agent behind the card | Spawn is disabled behind it | the home's **New agent** is off, with "Off until a compatible oats CLI is installed." | The Desktop's rule, with its reason beside the control. |
| A version that could not be read at all, while the roster reads | Spawn stays off "while no compatible CLI is verified" (the card, with what was tried) | "The installed oats could not be checked.", one muted line with **Check again**; **New agent** stays on | A roster that reads proves `oats` runs, and the kernel refuses a spawn it cannot make: one failed `oats version` is no reason to turn the act off. The home tries the read once more by itself first, and is not silent when that fails too. |
